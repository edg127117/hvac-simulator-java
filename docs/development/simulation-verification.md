# HVAC 仿真验证说明

本文件供开发者理解验证原则。Codex 的可执行流程位于 [`.agents/skills/hvac-simulation-verification/SKILL.md`](../../.agents/skills/hvac-simulation-verification/SKILL.md)，两处不要复制维护完整命令矩阵。

## 基本原则

- 可复现输入必须固定模型版本、时间范围、时区、时间步、参数、初始状态、随机种子、字段顺序、单位和参考资产版本。
- Python 模型是相应版本 Java 转换的行为参考；默认保持公式、参数、时间语义、单位、随机顺序和状态更新顺序。
- 基准模式按时间戳、每一行和每个字段比较，不能用图形或汇总值替代逐项对照。
- 浮点容差必须按公式规模、累计误差和业务意义说明依据，不能用过宽全局容差掩盖差异。
- 发现原模型疑似问题时先保存复现和差异证据，作为独立模型版本或任务处理，禁止在忠实转换中静默修正。
- 测试、Python/Java 一致性、物理合理性、性能、JAR、CSV、图表自动检查和视觉确认是不同证据。

## 验证范围

- 普通 Java 生产代码：相关定向测试和完整 `.\mvnw.cmd test`。
- 公式、参数、气象、随机测量、状态推进、时间语义、输出字段、模型版本或基准：增加逐时间步字段对照、容差说明和相关边界异常。
- 打包、资源、CLI 或交付产物：分别验证 package、JAR、CSV 和图表。
- 纯文档或规则：检查 Markdown 链接、关键术语、Skill、文件范围和 `git diff --check`，不机械运行无关模型测试。

普通测试不得依赖个人目录、当前系统时间、不可控随机输入或真实外部服务。冻结基准更新必须有独立设计、差异说明和可复现生成证据；禁止为了测试通过直接覆盖预期结果。
