# HVAC 仿真基准与结果验证规范

## 1. 适用范围

修改模型公式、状态推进、气象、配置、输出字段、CSV、图表、模型版本或参考资产时必须读取本文件。本规范用于区分“忠实复现”“自动化验证”“物理合理性验收”和“视觉确认”，这些结论不能互相替代。

## 2. 基本验证要求

提交前先运行与改动直接相关的定向测试；涉及 Java 生产代码时再运行仓库完整入口：

```powershell
.\mvnw.cmd test
```

涉及打包、资源、可执行入口或交付产物时补充：

```powershell
.\mvnw.cmd package
java -jar target\hvac-simulator-java.jar --weather=baseline --output=output
java -jar target\hvac-simulator-java.jar --weather=synthetic --seed=42 --output=output-synthetic
```

验证记录必须区分实际命令、成功、失败、跳过、未执行原因和需要人工确认的范围。测试失败时不得描述为可合并或已完成。

## 3. 可复现性

仿真测试和基准必须固定并记录：

- 模型版本、起止时间、时区和时间步长；
- 建筑、内部负荷、HVAC、气象和测量参数；
- 随机种子或版本化随机流；
- 初始状态、单位、符号和输出字段顺序；
- 参考资产、测试夹具和生成步骤的仓库版本。

普通测试不得依赖个人目录、临时文件、真实外部服务、当前系统时间或不可控随机输入。外部参考必须转为仓库内可追踪资产或明确生成步骤。

## 4. 忠实转换边界

Python 模型是相应版本 Java 转换的行为参考。转换默认保持公式、参数、时间语义、单位、随机顺序和状态更新顺序。

发现原模型疑似公式、参数、注释、单位或物理假设问题时：

1. 先保存最小复现、参考输出和差异证据；
2. 在当前兼容版本中保持既有基准；
3. 将物理修正、控制改进或语义调整作为独立模型版本和任务；
4. 禁止在忠实转换中静默修正或用宽容差掩盖差异。

Gaia 1.1 等包含随机测量模型的版本，必须先固定 Python 运行环境、依赖、随机基准、字段语义和参考图，再开始 Java 转换。相同字段名在不同模型版本中语义变化时，使用明确模型版本、指标编码和来源类型隔离。

## 5. 数值对照

基准模式按时间戳、行和字段逐项比较，不能只比较图形或汇总值。至少覆盖：

- 室内温度、室外温度和其他状态量；
- 冷负荷、设备功率、系统总功率；
- 冷机 COP 及模型版本新增的测量派生指标；
- 启停、死区、零负荷和容量边界；
- 时间序列长度、时间戳、字段名、字段顺序和单位。

浮点值不得直接精确相等。每类指标根据公式规模、累计误差和业务意义定义绝对/相对容差，并在测试或设计中说明依据。结果必须区分：

- 逐时间步差异；
- 汇总或统计差异；
- 允许数值误差；
- 已批准的模型版本差异。

出现 NaN、无穷值、除零、时间错位、字段缺失或超出合理范围时，测试应直接失败或返回明确异常，不能静默替换成看似合理的结果。

## 6. 边界与异常

按当前改动检查相关边界：

- 空调开启、关闭、死区和一分钟状态推进；
- 零负荷、最小负荷、额定负荷、容量上限和停机状态；
- 非法时间范围、非正时间步长、缺失参数和不合理物理参数；
- 数组长度、序列对齐、首末时间步和跨日边界；
- 温度、负荷、功率、流量、COP 和测量值的合理范围；
- 随机测量扰动、停机噪声和跨单位参数的版本兼容行为。

异常信息应能定位模型版本、参数或处理阶段，不依赖模糊的通用错误。

## 7. 交付产物分别验证

测试、JAR、CSV 和图表是不同证据，必须分别检查：

- 测试：定向测试和完整测试入口；
- JAR：可以按记录命令运行并返回预期退出状态；
- CSV：UTF-8、非空、字段/单位/顺序/时间戳/数据点数量正确；
- 图表：来自本次同一份真实仿真结果，文件非空，序列、时间范围、标题、坐标轴、单位和图例完整。

图表自动化检查不能代替视觉验收。交付领导确认前人工检查布局、曲线可读性、遮挡、中文字体、单位、尖峰位置和异常数据来源。图表可读不等于数值或物理行为已经验收。

## 8. 基准与生成文件边界

- 稳定参考资产放入版本化 `reference/` 或测试资源目录，并记录来源和生成方式；
- Maven `target/`、运行输出目录和临时依赖不进入 Git；
- 更新冻结基准必须有单独设计、差异说明和可复现生成证据；
- 不允许为了让测试通过直接覆盖预期结果；
- 参考 Python 环境缺失时可以使用临时受控环境验证，但最终稳定资产不能依赖个人绝对路径。

## 9. 结论表述

交付说明必须明确区分：

- 已实现并进入当前分支；
- 已执行自动化验证；
- 与 Python 基准一致；
- 已人工检查图表；
- 尚未完成物理合理性、性能、长期运行或领导验收；
- 仅设计、尚未实现的模型或平台能力。

不得把忠实一致性写成物理正确，也不得把设计文档写成运行能力。
