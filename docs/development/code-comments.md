# HVAC 仿真代码中文注释规范

## 1. 目标

修改 Java 生产代码时必须读取本文件。注释用于说明仿真职责、数据流、公式、单位、符号、时间语义、状态推进和兼容边界，不追求数量，不逐行翻译 Java。

## 2. 类级职责

新增或改变核心类时，使用简洁中文说明：

- 当前类负责哪一段仿真、配置、气象、模型、状态推进或输出流程；
- 上游输入来自哪里，下游结果交给谁；
- 它不负责哪些容易混淆的相邻职责；
- 使用哪个模型版本，以及是否承担兼容层、测量层或派生层职责。

已有类发生职责变化时同步更新说明。类名或包名已经完整表达的简单结构不重复注释。

## 3. 关键方法判定

关键方法由职责决定，不由可见性决定。以下方法需要就近说明：

- CLI 或仿真入口、主要阶段装配；
- 建筑热平衡、冷机、水泵、冷却塔、管网、FCU 等公式；
- 控制、设备启停、死区、时间步和状态更新；
- 气象、随机测量、功率表、测量制冷量和派生指标；
- 模型输入、内部状态、结果行、CSV 和图表之间的重要转换；
- 边界钳制、插值、舍入、数值保护和异常转换；
- 基准加载、原子文件输出和图表生成；
- 私有但由主流程依赖并承担完整仿真步骤的方法。

关键方法按需要说明：输入语义和单位、所处流程、使用公式或规则、状态副作用、输出去向、适用范围、异常和兼容行为。

## 4. 数值仿真专项说明

无法由类型和命名完整表达时，在最接近实现的位置说明：

- 公式来源、物理含义、简化假设和适用范围；
- 输入、输出和中间量的单位；
- 热量、负荷、功率、流量和温差的正负号约定；
- 时间步长、积分、初始条件和状态更新顺序；
- 额定值、上下限、死区和停机语义；
- 截断、钳制、插值、舍入和浮点容差的原因；
- 随机种子、随机流顺序和测量误差模型；
- 与 Python 基准保持一致但尚未完成物理合理性验收的行为；
- 同名字段在不同 Gaia 版本中的语义差异。

兼容性说明应描述当前真实行为，不写“以后修复”“本次先这样”等任务历史。疑似模型问题写入设计、状态或独立 issue，而不是在代码中留下模糊承诺。

## 5. 不需要添加的内容

通常不为以下内容添加注释：

- 普通 getter、setter、简单赋值、判空和委托；
- Maven、Java 或库的固定模板含义；
- 已由清晰命名表达的简单计算；
- 与类级或附近说明重复的内容；
- Java 语句的逐行中文翻译；
- 当前任务、提交、PR 或临时排查过程；
- 尚未实现的 Spring Boot、Vue、数据库或 MQTT 能力被描述为现状。

不得用注释掩盖职责过大、命名不清或难以测试的实现。

## 6. 修改后的完整检查

每次修改生产代码后检查完整文件，而不是只看 diff：

1. 新增或变化的职责是否准确说明；
2. 全部方法和构造器是否已按职责判定，私有关键方法是否遗漏；
3. 公式、单位、符号、状态、时间步和随机行为是否清楚；
4. 输入、输出、上下游和文件副作用是否清楚；
5. 原有注释是否仍与当前模型版本和实现一致；
6. 是否存在重复、逐行翻译、任务历史、未来设想或无信息说明；
7. 是否需要同步更新 `PROJECT_GUIDE.md` 或 `PROJECT_STATUS.md`。

## 7. 合格标准

- 维护者不必先读完整实现即可理解类在仿真链路中的位置；
- 关键公式和状态方法的输入、单位、规则、输出和限制明确；
- Gaia 版本、基准兼容和物理验收边界不会混淆；
- 私有关键方法没有因可见性遗漏；
- 注释简洁、准确、长期有效，不制造噪声。
