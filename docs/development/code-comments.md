# HVAC 仿真代码注释专项规则

通用注释质量由个人全局 `code-comment-quality` Skill 负责；本文件只补充 hvac-simulator-java 的仿真领域要求。修改或审查 Java 生产代码时，两者同时适用。

## 必须优先说明的内容

- 当前类或方法位于配置、气象、建筑热平衡、设备模型、状态推进、结果、CSV 或图表哪一段；
- 公式来源、物理含义、简化假设、适用范围，以及输入、输出和中间量单位；
- 热量、负荷、功率、流量和温差的正负号约定；
- 时间步、积分、初始条件、状态副作用和更新顺序；
- 额定值、上下限、死区、启停、钳制、插值、舍入和数值保护原因；
- 随机种子、随机流顺序和测量误差模型；
- Gaia 模型版本、Python 基准兼容以及同名字段跨版本的语义差异；
- 与基准一致但尚未完成物理合理性验收的边界。

不要逐行翻译、复述名称、记录任务历史、留下模糊未来承诺，或把尚未实现的 Spring Boot、Vue、数据库、权限和 MQTT 能力写成当前现状。疑似模型问题进入独立设计、状态或任务，不用注释暗中改变兼容语义。

## 检查范围

- 核心模型、公式、状态推进、随机行为、版本兼容和大范围重构：检查完整变化文件及相关调用链，复核已有注释时效。
- 普通生产 Java 修改：检查变化和受影响的方法、构造器或相邻契约。
- 纯注释、拼写、等价重命名或机械调整：只检查变化附近是否准确、简洁、无重复和无过期内容。

关键性由职责决定，不由 `public`、`private` 等可见性决定。简单 getter、setter、赋值、判空、委托和已由清晰命名表达的计算通常无需注释。
