# 设备运行时契约与公共能量数据模型设计

> 状态：已确认、待形成实施计划。
>
> 本文只定义自由拓扑平台第二子项目的公共运行时契约。它建立设备单步计算所需的数据、参数、状态、结果和错误边界，但不实现任何具体设备公式、拓扑执行或平台基础设施。

本文承接 [`通用自由拓扑仿真平台设计`](2026-08-10-free-topology-simulation-platform-design.md) 和已实施的 [`通用设备与拓扑引擎基础计划`](../plans/2026-08-10-generic-device-topology-engine-foundation.md)。[`Gaia 1.0 Java 忠实转换设计`](2026-08-04-gaia-java-port-design.md) 与 [`Gaia 1.1 模型接入设计`](2026-08-06-gaia-1.1-integration-design.md) 继续保持各自版本和验证边界，不因本公共契约改变。

## 1. 背景和结论

第一子项目已经实现公共能源枚举、端口静态契约、版本化设备静态定义、计算步长能力、只读设备目录、不可变拓扑图，以及候选连线和启动前基础结构校验。这些能力只能描述设备和连接，尚不能执行设备计算。

第二子项目采用“强类型公共快照 + 动态端口映射”方案：

- 自由拓扑继续使用稳定端口编号组织输入和输出；
- 电、水和控制信号使用密封强类型运行值，不使用 `Map<String, Object>`；
- 参数定义与完整参数值快照分离；
- 具体设备状态通过泛型保持类型安全；
- 单步计算显式返回成功结果或稳定错误；
- 引擎内部只接受规范单位，不负责外部单位换算；
- 所有公共对象保持不可变、防御性复制和确定性顺序。

本设计不表示自由拓扑已经可以运行。具体设备、拓扑编译、数据传播、闭环迭代和守恒求解仍属于后续子项目。

## 2. 目标和非目标

### 2.1 目标

本子项目建立：

1. 电、水和控制信号的强类型运行时值；
2. 统一的规范单位、有限值、方向和符号规则；
3. 版本化参数定义和完整参数快照；
4. 带模拟时间、步长、端口输入、参数和上一步状态的单步计算契约；
5. 带端口输出、指标和下一状态的成功结果；
6. 缺失输入、单位或介质不兼容、非有限值、除零、越界和不支持步长的稳定错误；
7. 面向后续 JSON、数据库和协议适配的稳定编码与版本边界。

### 2.2 明确排除

- 不实现或迁移冷机、水泵、冷却塔、管道、FCU、建筑负荷等具体公式；
- 不修改 Gaia 1.0 公式、参数、随机行为、时间语义、输出或冻结基准；
- 不实现 Gaia 1.1 Java 转换、传感器噪声、功率表误差或测量派生；
- 不实现拓扑编译、设备排序、数据传播、闭环迭代、质量/能量守恒或完整水力求解；
- 不实现 Spring Boot、Vue、数据库、MQTT、权限和任务管理；
- 不调整 Maven、JAR 或 CLI 结构；
- 不引入 Jackson、单位库或其他新依赖；
- 不把本子项目描述为完整自由拓扑仿真已经可执行。

## 3. 方案比较和选择

### 3.1 方案一：强类型公共快照与动态端口映射

运行值通过 `Map<String, PortValue>` 按端口编号组织，`PortValue` 再密封为电、水和三类控制信号。参数和状态保持强类型，单步计算返回密封结果。

优点是兼顾动态拓扑、编译期约束、稳定错误、确定性和未来序列化。代价是公共值对象较多，需要集中维护单位和不变量。

### 3.2 方案二：通用标量键值结构

端口、参数和状态统一使用 `Map<String, ScalarValue>`，依靠运行时模式描述类型、单位和范围。

优点是新增字段灵活。缺点是设备公式需要大量键查询和类型转换，介质和单位错误发现较晚，难以形成可靠的核心计算契约。

### 3.3 方案三：每个设备完全自定义输入输出

每种具体设备分别定义专属输入、输出和状态对象。

优点是具体设备类型约束最强。缺点是通用拓扑执行器无法统一调用不同设备，需要大量适配器，而且本子项目明确不实现具体设备。

### 3.4 最终选择

采用方案一。动态拓扑使用稳定端口编号，公共物理语义使用密封强类型对象，具体设备状态使用泛型，预期计算失败使用显式结果类型，外部格式由后续适配层转换。

## 4. 包和职责边界

在现有单 Maven 模块内新增三个逻辑子包：

```text
com.hvac.simulator.energy.runtime
  公共单位、质量状态、电/水/控制信号运行值和介质属性

com.hvac.simulator.device.parameter
  参数定义、受控参数值、约束和完整参数快照

com.hvac.simulator.device.runtime
  单步时间、设备状态、计算输入、输出、指标、结果、错误和单设备执行器
```

现有包继续承担原职责：

- `energy.EnergyType` 表示电、不同水系统和控制信号的静态能源类别；
- `device.port.PortDefinition` 表示端口编号、方向、介质、水侧、连接数和运行值规格；
- `device.DeviceDefinition` 表示版本化设备静态定义，并增加参数定义集合；
- `device.DeviceCatalog` 继续是只读静态定义目录；
- `topology` 继续只描述和校验连接，不执行设备计算。

`DeviceDefinition` 保留现有四参数便利构造方式并将参数集合初始化为空，以减少对第一子项目现有调用的破坏。`PortDefinition` 增加运行值规格后，现有仓库内调用点和测试必须显式补齐该规格，避免为控制端口猜测信号类型。

## 5. 规范单位、方向和公共编码

### 5.1 单位策略

引擎内部只接受规范单位，不自动换算。首版 `UnitCode` 至少包含：

| 编码 | 含义 |
|---|---|
| `NONE` | 无量纲或不适用 |
| `CELSIUS` | 摄氏度 |
| `KILOWATT` | 千瓦 |
| `KILOWATT_HOUR` | 千瓦时 |
| `KILOGRAM_PER_SECOND` | 千克每秒 |
| `PASCAL` | 帕 |
| `KILOGRAM_PER_CUBIC_METER` | 千克每立方米 |
| `JOULE_PER_KILOGRAM_KELVIN` | 焦耳每千克开尔文 |

未来 API、文件导入或协议适配器可以接收其他单位，但必须在进入引擎前显式转换。体积流量转换为质量流量需要介质密度，不能作为无条件的普通单位换算。

已有单位编码只允许增加新值，不能修改原有含义。持久化和协议使用稳定英文编码，不使用枚举序号。

### 5.2 方向和符号

- `INPUT` 表示值沿端口流入设备；
- `OUTPUT` 表示值沿端口流出设备；
- 有功功率、电能和质量流量只保存非负大小；
- 反向流动不能用负数暗示，必须由相反方向端口或后续单独设计的双向端口表达；
- 温度和控制设定值可以为负，但必须是有限值；
- 压力、密度和比热容采用各自明确的非负或正值约束。

### 5.3 质量状态

电、水和控制信号都使用统一 `QualityStatus`：

- `GOOD`：值可正常使用；
- `UNCERTAIN`：值存在不确定性；
- `BAD`：值已知不可靠；
- `NOT_AVAILABLE`：当前没有有效值。

质量状态描述整个端口快照。本子项目不扩展为逐字段测点质量模型。

公共单设备执行器只校验质量状态存在，不统一拒绝 `UNCERTAIN`、`BAD` 或 `NOT_AVAILABLE`。不同设备是否可以继续计算、使用备用值、降低输出质量或返回错误，由具体设备运行时根据自身公式决定；公共层不能替所有设备制定同一降级策略。

## 6. 端口运行值

### 6.1 端口运行值规格

`PortDefinition` 增加密封 `PortValueSpec`，用于声明一个端口实际接受的运行值类型：

- `ElectricalPortValueSpec`；
- `WaterPortValueSpec`，包含期望介质编码；
- `SetpointSignalSpec`，包含设定值规范单位；
- `StartStopSignalSpec`；
- `ModeSignalSpec`，包含有序的允许模式编码集合。

运行值规格必须与现有 `EnergyType` 一致。电端口只能使用电规格，水端口只能使用水规格，控制信号端口只能使用三类控制规格之一。水端口原有 `WaterSide` 规则继续有效。

### 6.2 密封运行值

`PortValue` 密封为：

#### 电运行值

`ElectricalPortValue` 包含：

- 有功功率，规范单位 `KILOWATT`；
- 电能，规范单位 `KILOWATT_HOUR`；
- `SupplyStatus`：`AVAILABLE`、`UNAVAILABLE` 或 `UNKNOWN`；
- `QualityStatus`。

功率和电能必须为有限非负值。供电状态不通过特殊功率数值表达。

#### 水运行值

`WaterPortValue` 包含：

- 温度，规范单位 `CELSIUS`；
- 质量流量，规范单位 `KILOGRAM_PER_SECOND`；
- 压力；
- `FluidProperties`；
- `QualityStatus`。

压力使用密封类型表达“已知有限非负 Pa 值”或“明确不可用”，不使用 `null`、`NaN`、`-1` 等哨兵。

`FluidProperties` 包含稳定介质编码、有限正密度和有限正比热容。首版正式介质为 `WATER`。它只保存本步计算使用的物性，不负责根据温度或配比计算物性。

#### 控制信号

控制信号拆分为三个独立运行值：

- `SetpointSignalValue`：有限数值、`UnitCode` 和质量状态；
- `StartStopSignalValue`：`START` 或 `STOP` 和质量状态；
- `ModeSignalValue`：稳定模式编码和质量状态。

控制信号不使用一个带多个空字段的万能对象。设定值单位和模式编码必须符合端口运行值规格。

## 7. 参数定义和值快照

### 7.1 参数值和约束

`ParameterValue` 支持四种受控类型：

- `DecimalParameterValue`：有限 `double` 和 `UnitCode`；
- `IntegerParameterValue`：`long` 和 `UnitCode`；
- `BooleanParameterValue`：布尔值，单位固定为 `NONE`；
- `EnumParameterValue`：稳定非空编码，单位固定为 `NONE`。

参数约束使用匹配类型的密封对象：小数闭区间、整数闭区间、枚举允许值集合或无额外约束。定义创建时必须拒绝类型、单位、默认值和约束不一致的组合。

### 7.2 参数定义

`ParameterDefinition` 包含：

- 参数编码；
- 中文名称；
- 参数类型；
- 默认值；
- 规范单位；
- 范围或枚举允许值；
- 生效状态。

生效状态固定为：

| 状态 | 参与计算 | 允许修改 |
|---|---:|---:|
| `CONFIGURABLE_CALCULATION` | 是 | 是 |
| `FIXED_CALCULATION` | 是 | 否 |
| `NOT_USED_IN_CALCULATION` | 否 | 否 |

`modifiable()` 和 `usedInCalculation()` 由生效状态得出，避免保存互相冲突的布尔字段。

### 7.3 完整参数快照

`ParameterSnapshot` 保存设备模块键和该版本全部参数的最终值。它不复制参数说明书，也不保存用户修改历史。

新任务从定义默认值开始，只接受 `CONFIGURABLE_CALCULATION` 参数的覆盖值，最后生成完整快照。恢复历史任务时要求序列化数据包含完整参数集合，并按相同设备版本重新校验。

固定参数和当前未接入计算的参数仍进入快照，以保证任务记录完整；它们不能被覆盖。设备公式只能读取定义为参与计算的参数，不能因为快照保存了未接入参数就使用它。

快照创建后不可修改。计算阶段不补默认值，也不读取可变外部参数目录。

## 8. 单步设备计算契约

### 8.1 时间和输入

`SimulationStepContext` 包含：

- 带时区的模拟时间；
- 正数计算步长 `Duration`。

`DeviceCalculationInput<S extends DeviceState>` 包含：

- `SimulationStepContext`；
- 按端口编号组织的只读输入值；
- 完整 `ParameterSnapshot`；
- 上一步状态 `S`。

无状态设备使用明确的 `StatelessDeviceState`，禁止使用 `null`。

### 8.2 状态泛型和版本

`DeviceRuntime<S extends DeviceState>` 声明：

- 对应 `DeviceModuleKey`；
- `DeviceStateDescriptor<S>`；
- 单步计算方法。

状态描述包含稳定状态编码、正整数结构版本和 Java 状态类型。未来序列化适配器使用“设备模块键 + 状态编码 + 状态结构版本”选择转换方式，不依赖 Java 完整类名。

具体设备状态必须是不可变对象；如包含集合，需要防御性复制并由设备级契约测试验证。

### 8.3 成功结果

`DeviceCalculationResult<S>` 包含：

- 按输出端口编号组织的 `PortValue`；
- 按稳定指标编码组织的 `DeviceMetricValue`；
- 下一状态 `S`。

指标值支持小数、整数、布尔和枚举标量，并显式携带规范单位和质量状态。它只表示本步设备指标，不建立完整平台测点目录，也不引入 Gaia 1.1 的指标来源分类。

### 8.4 显式计算结果

`CalculationOutcome<S>` 是密封结果：

- `CalculationSuccess<S>` 携带 `DeviceCalculationResult<S>`；
- `CalculationFailure<S>` 携带一个 `DeviceCalculationError`。

预期输入或数值问题通过失败结果返回，不使用受检或非受检异常表达。空引用、非法对象构造、错误状态 Java 类型和设备实现缺陷仍属于编程错误。

## 9. 公共单设备执行器

`SingleDeviceStepExecutor` 只执行一个已经选定的设备运行时，不查找拓扑上下游。

执行顺序为：

1. 检查静态定义与运行时模块键；
2. 检查状态类型和参数快照版本；
3. 检查计算步长；
4. 按静态定义顺序检查必需输入；
5. 检查输入端口方向、运行值类型、单位、介质和范围；
6. 调用设备单步计算；
7. 若设备返回失败则原样返回；
8. 检查成功结果的输出端口、运行值和下一状态；
9. 按稳定顺序冻结输出与指标后返回成功。

输入映射按端口定义顺序规范化，参数按参数定义顺序保存，输出按输出端口定义顺序规范化，指标按稳定编码排序。相同输入必须得到字段和值顺序一致的结果。

该执行器不传播端口值、不决定设备顺序、不迭代闭环、不做守恒或水力求解，因此不属于完整拓扑执行器。

## 10. 稳定错误和中文展示

### 10.1 错误编码

首版 `DeviceCalculationErrorCode` 为：

| 稳定编码 | 固定中文名称 |
|---|---|
| `MISSING_INPUT` | 缺少输入 |
| `INCOMPATIBLE_VALUE_TYPE` | 端口值类型不兼容 |
| `INCOMPATIBLE_UNIT` | 单位不兼容 |
| `INCOMPATIBLE_MEDIUM` | 介质不兼容 |
| `NON_FINITE_VALUE` | 数值不是有限值 |
| `DIVISION_BY_ZERO` | 计算发生除零 |
| `NUMERIC_OUT_OF_RANGE` | 数值超出范围 |
| `UNSUPPORTED_TIME_STEP` | 不支持的计算步长 |

`DeviceCalculationError` 包含：

- 稳定英文编码；
- 固定中文名称；
- 中文具体说明；
- 设备模块键；
- 模拟时间；
- 关联对象类型和端口、参数或指标编码；
- 有序结构化详情。

前端主要显示中文名称和中文具体说明。英文编码用于程序判断、日志、诊断和后续多语言映射。前端不自行维护另一套中文错误名称。

### 10.2 错误优先级

一次计算只返回第一个错误，检查顺序固定为：

```text
计算步长
→ 参数快照
→ 必需输入
→ 端口运行值类型
→ 单位
→ 介质
→ 有限值和范围
→ 设备公式
→ 输出结果
```

同类端口和参数按静态定义顺序检查，保证相同非法输入始终得到相同首要错误。

非有限的外部原始文本或协议数据尚未构造成合法领域值时，由未来适配层使用同一稳定错误编码报告；合法领域值对象本身不保存 `NaN` 或无穷。设备公式产生非有限中间量或输出时，运行时返回 `NON_FINITE_VALUE`。

### 10.3 编程错误

以下情况属于代码装配或设备实现缺陷，不伪装成普通仿真错误：

- 运行时模块键与静态定义不一致；
- 上一步状态 Java 类型错误；
- 设备返回未声明的输出端口；
- 设备实现抛出未预期程序异常。

它们使用 `IllegalArgumentException` 或 `IllegalStateException` 立即失败，未来由任务层记录为程序故障。

## 11. 不可变性和确定性

公共记录和类必须：

- 拒绝空引用、空白稳定编码和不合法组合；
- 对列表、集合和映射进行防御性复制；
- 返回不可修改视图；
- 对需要确定顺序的映射使用 `LinkedHashMap` 复制和只读包装，不依赖无序映射遍历；
- 不使用 `null`、`NaN`、无穷或特殊负数表达缺失状态。

确定性定义为：相同设备版本、模拟时间、步长、端口输入、参数快照和上一步状态，必须产生完全相同的成功结果或错误。

设备运行时不得读取系统当前时间、环境变量、外部服务或全局随机数。本子项目不实现随机测量；未来随机设备必须把随机流版本、种子和序列位置作为显式设备状态或版本化输入保存，使相同随机状态可重复产生相同结果。

## 12. 序列化兼容边界

领域对象不添加 Jackson 注解。未来 API、数据库或协议层使用独立 DTO，并至少保存：

```text
schemaVersion
valueType
unitCode
qualityCode
deviceType
moduleVersion
stateCode
stateSchemaVersion
```

持久化和协议不能使用 Java 类名、枚举序号或 `toString()` 作为稳定契约。已有编码不能改变含义；同名字段语义变化时必须提升结构版本或设备模块版本。中文名称用于展示，稳定英文编码用于程序和存储。

本子项目只建立上述领域边界和版本标识，不实现 JSON、数据库、MQTT 或状态编解码器。

## 13. 测试设计

实施时使用测试用假设备验证公共契约，不实现任何真实设备公式。

### 13.1 端口运行值测试

- 功率、电能、质量流量、压力、密度和比热容的有限值及符号约束；
- 压力可用与不可用两种明确状态；
- 电、水和控制信号规格匹配；
- 设定值单位、启停命令和模式允许值；
- 四种质量状态；
- 集合防御性复制和不可修改性。

### 13.2 参数测试

- 四种参数类型、默认值、单位和约束匹配；
- 小数和整数闭区间边界；
- 枚举允许值；
- 固定参数和未接入参数不可覆盖；
- 新任务默认值解析后形成完整快照；
- 历史恢复要求完整参数集合；
- 未知参数、错误类型和错误单位被拒绝；
- 参数及快照顺序确定。

### 13.3 单步计算测试

- 支持与不支持的计算步长；
- 缺失输入、错误端口值类型、错误单位和错误介质的稳定中文错误；
- 公共执行器不因 `UNCERTAIN`、`BAD` 或 `NOT_AVAILABLE` 自动拒绝输入；
- 设备运行时返回非有限、除零和越界错误；
- 成功结果包含输出、指标和下一状态；
- 无状态设备不使用 `null`；
- 同一输入重复执行得到完全相同结果；
- 多个错误同时存在时返回固定首要错误；
- 模块键、状态类型和未声明输出等编程错误被识别。

### 13.4 回归和交付验证


本子项目不调整打包、资源、CLI、CSV 或图表，因此不要求重新生成 JAR、CSV 和 PNG。验证必须同时检查 Gaia 1.0 生产行为和冻结基准没有变化，Gaia 1.1 仍为未实现状态。
